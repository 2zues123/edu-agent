# 高校教务教学智能体应用计划

## 1. 项目定位

本项目拟实现一个面向高校学生教务咨询与课程学习支持的 Agent 应用。系统基于大模型、知识库增强生成和流程编排能力，围绕教务政策问答、课程与培养方案咨询、考试成绩事务、办事流程引导和学习规划建议等场景，为学生提供可追溯、可解释、可扩展的智能服务。

项目不定位为通用聊天机器人，而是定位为“懂学校制度、懂培养方案、能引导学生完成教务问题初步判断的高校教务教学智能体”。

## 2. 建设目标

1. 构建教务政策、培养方案、课程资料和办事流程四类知识库。
2. 支持学生围绕学分、选课、补考、重修、缓考、成绩复核、毕业要求等问题进行问答。
3. 支持基于课程资料的学习答疑、学习路径建议和复习计划生成。
4. 对涉及成绩、毕业、学籍、处分等高风险事项提供依据引用和谨慎提示。
5. 通过意图识别、多轮追问、检索增强、流程引导和风险校验体现 Agent 能力。
6. 提供可演示的 Web 应用界面，适合 3-5 分钟比赛路演展示。

## 3. 用户角色

### 3.1 学生

主要使用者，关注政策理解、学分进度、课程学习、考试事务和办事流程。

### 3.2 教师

辅助回答课程学习问题、课程要求说明、教学安排说明等高频问题。

### 3.3 教务管理人员

通过系统减少重复咨询，维护政策文件、培养方案、常见流程和 FAQ。

## 4. 核心功能

### 4.1 教务政策问答

学生可以咨询学籍管理、选课管理、成绩管理、考试管理、补考重修、缓考申请、转专业、休复学、毕业资格等问题。

回答结构建议为：

```text
结论
依据来源
适用条件
注意事项
后续办理建议
```

当知识库没有检索到明确依据时，系统应说明无法确认，并建议咨询学院教务办公室。

### 4.2 课程与培养方案咨询

支持查询专业培养目标、毕业要求、课程体系、必修课、选修课、实践课、模块学分要求和推荐修读学期。

学生输入专业、年级、已修课程和目标方向后，系统可输出：

1. 当前学分完成情况。
2. 缺失模块和课程。
3. 后续选课建议。
4. 与毕业要求相关的风险提醒。

### 4.3 考试与成绩事务助手

支持缓考申请、补考重修、成绩复核、考试违纪规则、课程成绩组成等问题。

对于成绩、学籍、毕业资格等高风险问题，系统必须输出风险提示：

```text
该问题涉及正式教务认定，系统仅根据当前知识库做初步判断，最终结果以教务系统和学院审核为准。
```

### 4.4 办事流程引导

系统根据学生问题识别是否属于流程类事务，并输出办理步骤、材料清单、办理入口、负责部门和截止时间提醒。

典型流程包括：

1. 缓考申请。
2. 成绩复核。
3. 重修报名。
4. 学籍异动申请。
5. 证明材料办理。

### 4.5 课程学习答疑

系统支持基于课程资料的知识性问答，例如编程、人工智能、数学基础、软件工程等课程内容。

回答应优先基于课程大纲、课件、实验指导书和 FAQ。若问题超出课程资料范围，系统可以给出通用学习建议，但需说明不是来自课程文件。

### 4.6 个性化学习规划

学生输入专业、年级、兴趣方向、已修课程和薄弱课程后，系统生成学习规划建议。

输出内容包括：

1. 短期课程补强建议。
2. 中期专业方向学习路径。
3. 项目实践建议。
4. 复习计划。
5. 学分和毕业风险提醒。

## 5. Agent 工作流

```text
用户输入问题
    ↓
意图识别
    ↓
问题分类
    ├─ 教务政策问题
    ├─ 培养方案问题
    ├─ 考试成绩事务
    ├─ 办事流程问题
    └─ 课程学习问题
    ↓
必要信息检查
    ↓
若信息不足，进行多轮追问
    ↓
检索对应知识库
    ↓
答案生成
    ↓
风险校验
    ↓
输出结构化回答、依据引用和办理建议
```

## 6. 模块设计

### 6.1 前端交互模块

提供聊天式交互界面，并展示引用来源、追问信息、流程步骤和风险提醒。

建议包含：

1. 问答对话区。
2. 引用依据区。
3. 办事流程卡片。
4. 学分规划结果区。
5. 知识库文件管理入口。

### 6.2 意图识别模块

负责识别用户问题类型，并决定调用哪个处理流程。

初期可使用规则关键词和大模型分类结合的方式，例如：

1. “挂科、补考、重修”归入考试成绩事务。
2. “学分、毕业、培养方案”归入培养方案咨询。
3. “怎么申请、需要材料、流程”归入办事流程。
4. “解释、概念、代码、算法”归入课程学习答疑。

### 6.3 知识库检索模块

负责从教务政策、培养方案、课程资料、办事流程中检索相关内容。

建议每条检索结果保留：

1. 文档名称。
2. 所属类别。
3. 章节标题。
4. 原文片段。
5. 更新时间。

### 6.4 答案生成模块

基于用户问题、检索结果和系统模板生成结构化回答。

政策类回答必须包含依据。学习类回答可以包含例子、步骤和练习建议。

### 6.5 风险校验模块

识别高风险问题并强制加入谨慎提示。

高风险关键词包括：

1. 毕业资格。
2. 学籍处理。
3. 退学、休学、复学。
4. 成绩认定。
5. 违纪处分。
6. 学位授予。

### 6.6 流程引导模块

将办事类问题转化为可执行步骤，输出材料、入口、部门、时间要求和注意事项。

### 6.7 学习规划模块

根据学生信息和培养方案进行规则判断，生成学分缺口、课程建议和学习路径。

## 7. 知识库设计

### 7.1 教务政策库

包含学籍管理规定、选课管理办法、考试管理办法、成绩管理办法、补考重修规定、缓考规定、转专业规定、休复学规定等。

### 7.2 专业培养方案库

包含专业培养目标、毕业要求、课程体系、模块学分、推荐修读学期、先修课程关系等。

### 7.3 课程资料库

包含课程大纲、教学进度表、实验指导书、作业要求、考核方式说明和课程 FAQ。

### 7.4 办事流程库

包含缓考申请、成绩复核、重修报名、学籍异动、证明办理等流程说明。

## 8. 技术路线

### 8.1 原型阶段

使用 Python 实现核心逻辑，优先保证功能闭环。

建议技术栈：

1. Streamlit 或 Gradio：快速构建演示界面。
2. LangChain 或 LlamaIndex：实现文档切分、检索和 RAG 流程。
3. FAISS 或 Chroma：本地向量检索。
4. SQLite 或 JSON：保存用户配置、课程信息和知识库元数据。
5. OpenAI API 或兼容大模型接口：完成意图识别和答案生成。

### 8.2 工程化阶段

在原型稳定后，可扩展为前后端分离应用。

可选技术栈：

1. FastAPI：后端服务。
2. React 或 Vue：前端界面。
3. PostgreSQL：结构化数据。
4. Milvus、Chroma 或 pgvector：向量检索。
5. Docker：部署和演示环境封装。

## 9. 数据准备计划

第一阶段先使用模拟数据和样例文档完成演示闭环。

样例数据包括：

1. `本科生学籍管理规定.md`
2. `考试与成绩管理办法.md`
3. `软件工程专业培养方案.md`
4. `缓考申请流程.md`
5. `FastAPI课程实验指导.md`

第二阶段再替换为真实学校公开文件或比赛允许使用的材料。

## 10. 演示场景

### 10.1 学分毕业咨询

学生输入：

```text
我是软件工程专业大三学生，现在已修 120 学分，毕业要求 160 学分，我还差哪些模块？
```

系统输出总学分缺口、模块缺口、后续选课建议和毕业风险提醒。

### 10.2 挂科与重修咨询

学生输入：

```text
我高数挂科了，会不会影响毕业？
```

系统追问课程性质、是否必修、学分和当前年级，再给出初步判断。

### 10.3 课程学习答疑

学生输入：

```text
FastAPI 中 GET 和 POST 有什么区别？
```

系统基于课程资料给出概念解释、代码示例和练习建议。

### 10.4 缓考申请流程

学生输入：

```text
我考试当天生病了，怎么申请缓考？
```

系统输出申请条件、材料清单、办理步骤、截止时间和风险提示。

## 11. 开发里程碑

### 11.1 第 1 阶段：基础原型

1. 创建基础 Web 界面。
2. 准备样例知识库文档。
3. 实现文档加载和简单检索。
4. 实现基础问答。

验收标准：能够基于样例文档回答政策类问题，并显示引用来源。

### 11.2 第 2 阶段：Agent 工作流

1. 实现意图识别。
2. 实现问题分类。
3. 实现多轮追问。
4. 实现高风险问题识别和提示。
5. 实现办事流程结构化输出。

验收标准：不同类型问题进入不同回答模板，流程类问题能输出步骤。

### 11.3 第 3 阶段：学习规划

1. 建立培养方案样例数据。
2. 建立课程模块和学分规则。
3. 实现学分缺口计算。
4. 输出学习路径和选课建议。

验收标准：学生输入专业、年级、已修学分后，系统能给出初步规划。

### 11.4 第 4 阶段：演示优化

1. 优化界面布局。
2. 增加引用依据展示。
3. 准备 4 个典型演示问题。
4. 录制 3-5 分钟演示脚本。
5. 完成项目说明文档。

验收标准：可完整展示政策问答、流程引导、课程答疑和学习规划。

## 12. 最小可行版本范围

MVP 只做以下能力：

1. 本地样例知识库。
2. 聊天式问答界面。
3. 意图识别。
4. RAG 检索回答。
5. 引用来源展示。
6. 高风险问题提示。
7. 缓考、重修、学分咨询三个演示流程。

暂不做真实教务系统登录、真实成绩查询、自动提交申请、教师端审批和复杂权限管理。

## 13. 风险与规避

### 13.1 政策幻觉风险

规避方式：政策类回答必须引用知识库来源；无依据时不强答。

### 13.2 个人隐私风险

规避方式：MVP 不接入真实学生身份和成绩数据，只使用用户手动输入的模拟信息。

### 13.3 项目边界发散

规避方式：功能限定为教务政策问答、课程学习答疑、办事流程引导和学习规划建议。

### 13.4 演示不聚焦

规避方式：围绕四个固定场景准备数据、问题和回答，不展示无关闲聊能力。
